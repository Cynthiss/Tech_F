Contrato Token.sol

// SPDX-License-Identifier: MIT
pragma solidity ^0.8.28;

import {ERC20} from "@openzeppelin/contracts/token/ERC20/ERC20.sol";

contract Token is ERC20 {
    address public feeReceiver;

    constructor(address _feeReceiver) ERC20("Lab Token", "LAB") {
        feeReceiver = _feeReceiver;
        _mint(msg.sender, 1_000_000 * 10 ** decimals());
    }

    function _update(address from, address to, uint256 value) internal override {
        if (from == address(0) || to == address(0)) {
            super._update(from, to, value);
            return;
        }

        uint256 fee = value / 100;
        uint256 amountAfterFee = value - fee;

        super._update(from, feeReceiver, fee);
        super._update(from, to, amountAfterFee);
    }
}

Pruebas implementadas

  • Unit Test: verifica que una transferencia envíe correctamente el 1% al feeReceiver.
  • Fuzz Test: prueba múltiples montos aleatorios para validar que el fee siempre sea correcto.
  • Invariant Test: valida que el totalSupply permanezca constante durante las operaciones.

Deploy a Sepolia Ethereum

Configuración completada · despliegue preparado

Se configuró la infraestructura necesaria para realizar el despliegue en Sepolia: wallet de MetaMask, RPC de Alchemy, variables de entorno y comando de despliegue. Durante la ejecución se identificó una limitación externa relacionada con la disponibilidad de Sepolia ETH para cubrir el gas de la transacción.

Comando utilizado

forge create src/Token.sol:Token \
  --rpc-url "$SEPOLIA_RPC_URL" \
  --private-key "$PRIVATE_KEY" \
  --broadcast \
  --constructor-args "$FEE_RECEIVER"

Error obtenido

Error: server returned an error response:
error code -32000: gas required exceeds allowance (0)
El contrato quedó listo para ser desplegado inmediatamente en Sepolia una vez la wallet disponga de Sepolia ETH para pagar el gas.

Intentos de obtener Sepolia ETH

  • Alchemy Faucet: requería saldo mínimo en Ethereum Mainnet.
  • Google Cloud Faucet: entregó PYUSD de prueba, no ETH para gas.
  • QuickNode Faucet: requería saldo en Ethereum Mainnet.
  • Chainlink Faucet: requería LINK en Ethereum Mainnet para solicitar ETH.

Conclusión

El laboratorio permitió implementar un token ERC20 con lógica personalizada de transferencia mediante un fee del 1%. Se validó su comportamiento mediante pruebas unitarias, fuzz tests e invariant tests. Además, se generó el reporte de gas y se realizó correctamente el despliegue local en Anvil.

El despliegue en Sepolia quedó técnicamente preparado y documentado. La única limitación encontrada fue externa al código: la falta de Sepolia ETH disponible para cubrir el gas debido a restricciones de los faucets públicos.
