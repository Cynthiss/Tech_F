Resumen del laboratorio

Flujo realizado

1. SubirSe sube venture-hello.json con un script que rechaza correos, números largos, JWT y llaves privadas.
2. CIDPinata devuelve el identificador derivado del hash del contenido.
3. PinSe confirma el pin activo en el dashboard y con npm run list.
4. ResolveSe abre /ipfs/<CID> en el gateway y se comparan los bytes con el archivo local.

STORAGE.md: política de datos

Los datos del venture se clasifican por sensibilidad y durabilidad, y de esa combinación sale el destino.

DatoSensibilidadDurabilidadDestino
Landing, imágenes y assets de marketingPúblicoMesesLocation-addressed (hosting/CDN)
Documentos públicos que no cambianPúblicoAñosIPFS + pin (Pinata)
Artefacto del lab (venture-hello.json)PúblicoEfímeroIPFS + pin, como evidencia temporal
Notas y logs de operaciónInternoEfímero / mesesLocation-addressed
Llaves, API keys y JWTInterno (crítico)EfímeroNever-permanent: gestor de secretos
Datos de clientesPIIAñosNever-permanent: base cifrada con borrado
KYC y registros AMLRegulatedSegún leyNever-permanent: sistema auditable y borrable, nunca IPFS
Hash de un acta firmada (no el documento)PúblicoPermanenteRaro candidato a permanencia

Promesas que NO haremos

  • "Borramos todo cuando cierras la cuenta" para contenido ya publicado con un CID público.
  • "Si editas el documento, la versión vieja desaparece": el CID viejo sigue vivo mientras alguien lo pinnee.
  • "Cumplimos el derecho al olvido" o "retiramos el contenido de internet" tras un reporte de abuso.

Promesa que SÍ haremos

Que cada documento público tenga un CID verificable que prueba que no cambió, y mantenerlo pinneado mientras el venture opere, avisando antes de quitar el pin.

Seguridad

  • El JWT de Pinata vive solo en un archivo .env local, que está en .gitignore. La API key se creó con permisos mínimos.
  • No se subió PII ni KYC: lo que se pinnea en IPFS público no se puede borrar de la red.
